# LoomKit — Hermes Project Instructions

LoomKit is a spec-driven design framework with TDD superpowers. This `HERMES.md` sets project-level instructions for Hermes agents.

## Workflow Commands (Hermes Skills)

Instead of slash commands, Hermes loads LoomKit phases as skills:

| Phase     | Skill Name             | Action                                      |
|-----------|------------------------|---------------------------------------------|
| Intent    | `loomkit-intent`       | Capture problem, outcome, non-goals         |
| Spec      | `loomkit-spec`         | Requirements + WHEN/THEN scenarios          |
| Design    | `loomkit-design`       | Architecture + test strategy                |
| Plan      | `loomkit-plan`         | Bite-sized TDD tasks with exact code        |
| Verify    | `loomkit-verify`       | Coverage gate + test run                    |
| Archive   | `loomkit-archive`      | Merge specs, archive change                 |

## How to Use with Hermes

1. Symlink or copy skills from this adapter into `~/.hermes/skills/`
2. Load the skill with `skill_view(name='loomkit-intent')` (or equivalent)
3. Follow the phase order strictly: **Intent → Spec → Design → Plan → Verify → Archive**

## TDD Enforcement Rules (Hermes)

- **Iron Law**: No production code without a failing test first.
- Every task in `tasks.md` must follow **RED → GREEN → REFACTOR**.
- Traceability: Every test references a scenario ID (`SC-001`).
- Coverage gate must pass before archiving.

## Adapter Notes for Hermes

- Hermes uses **file-based skills** (SKILL.md) instead of slash commands.
- This adapter provides reusable `SKILL.md` templates for each LoomKit phase.
- Skills should be placed in `~/.hermes/skills/loomkit-*` or symlinked.
- Use `skill_manage` or direct file operations to install.
